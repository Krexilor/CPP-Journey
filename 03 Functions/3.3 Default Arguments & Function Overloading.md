## Overview
C++ offers two complementary ways to make functions more flexible at the call site: **default arguments** (skip optional parameters) and **function overloading** (multiple functions sharing a name with different signatures).

## Default Arguments
A parameter can have a **default value**, which is used automatically if the caller doesn't provide one.

```cpp
void greet(string name, string greeting = "Hello") {
	cout << greeting << ", " << name << "!" << endl;
}

int main() {
	greet("Krex");
	greet("Krex", "Welcome back");
	return 0;
}
```

### Rule: Defaults Must be Trailing
Once a parameter has a default value, **every parameter after it** must also have one. You cannot have a non-default parameter following a default one.

```cpp
// Valid
void func(int a, int b = 10, int c = 20) { }

// InValid - compile error
void func(int a = 5, int b, int c) { }
```

> [!WARNING]
> Default arguments are resolved at **compile time** based on the function declaration, not the definition. If declared in a header file, set the defaults there - not in the `.cpp` definition - or you'll get a redefinition error.

### Practical Example
```cpp
double calculateInterest(double principal, double rate = 5.0, int years = 1) {
	return principal * (rate / 100) * years;
}

int main( ) {
	cout << calculateInterest(1000) << endl;             // uses rate = 5.0, years = 1
	cout << calculateInterest(1000, 7.5) << endl;        // uses years = 1
	cout << calculateInterest(1000, 7.5, 3) << endl;     // all provided
	return 0;
}
```

## Function Overloading
**Overloading** allows multiple functions to share the same name as long as their **parameter lists differ** (different number of parameters, or different types).

```cpp
int add(int a, int b) {
	return a + b;
}

double add(double a, double b) {
	return a + b;
}

int add(int a, int b, int c) {
	return a + b + c;
}

int main( ) {
	cout << add(2, 3) << endl;         // calls int version → 5
	cout << add(2.5, 3.5) << endl;     // calls double version → 6.0
	cout << add(1, 2, 3) << endl;      // calls 3-param version → 6
}
```

The compiler determines **which overload to call** based on the number and types of arguments at the call site - this is resolved at compile time, known as **static (compile-time) polymorphism**.

> [!NOTE]
> The return type **along** cannot distinguish overloads. Two functions with the same name and same parameters but different return types will cause a compile error - the parameter list must differ.

```cpp
// InValid - only return type differs, this will not compile
int getValue( );
double getValue( );
```

## Overloading vs Default Arguments - Avoiding Ambiguity
Combining both features carelessly can create **ambiguous calls** the compiler cannot resolve.

```cpp
void display(int a, int b = 10) { }
void display(int a) { }

// display(5);   // Error: ambiguous could match either function
```

> [!NOTE]
> When designing a function's interface, decide deliberately between overloading (truly different behavior per type/count) and default arguments (same behavior, optional parameters). Mixing both for the same function name often leads to ambiguity errors.

## Why These Matter
* **Default arguments** reduce the need to write multiple near-identical overloads just to support optional parameters.
* **Function overloading** lets your API read naturally - `print(int)`, `print(string)`, `print(double)` - instead of forcing awkward names like `printInt`, `printString`, `printDouble`.
