## Overview
A **function** is a named, reusable block of code that performs a specific task. The **function signature** is the contract that defines how a function can be called - its name, the types of data it accepts, and the type of data it returns.

## Anatomy of a Function

```cpp
returnType functionName(parameterType parameterName) {
	// function body
	return value;
}
```

```cpp
int add(int a, int b) {
	return a + b;
}
```

* `int` → **Return type**. The type of value this function sends back.
* `add` → **Function name**. Used to call the function elsewhere.
* `(int a, int b)` → **Parameter list**. The inputs the function accepts.
* `return a + b;` → Sends the result back to the caller.

> [!NOTE]
> A function's **signature** technically refers to its name plus its parameter types (not the return type). This distinction matters later for function overloading - two functions can share a name if their parameter lists differ, even with the same return type.

## Declaration vs Definition
A function can be **declared** (its signature only, no body) separately from where it's **defined** (the full implementation).

```cpp
// Declaration (also called a "prototype")
int add(int a, int b);

int main( ) {
	cout << add(3, 4) << endl;     // Works because the compiler knows the signature
	return 0;
}

// Definition (comes later, or in a separate .cpp file)
int add(int a, int b) {
	return a + b;
}
```

> [!TIP]
> Declarations are essential in larger projects. They go in header files (`.h`) so multiple `.cpp` files can call a function without needing its full implementation - only its signature.

## The `void` Return Type
A function that performs an action but does not return any value uses `void`.

```cpp
void greet(string name) {
	cout << "Hello, " << name << "!" << endl;
	// No return statement needed
}

int main( ) {
	greet("Krex");
	return 0;
}
```

> [!WARNING]
> A `void` function cannot be used in an expression that expects a value. `int x = greet("Krex");` is a compile error - `greet` returns nothing to assign.

## Calling a Function
Calling a function temporarily transfers program execution into that function's body. Once it finishes (or hits a `return`), control returns to the line right after the call.

```cpp
int square(int n) {
	return n * n;
}

int main( ) {
	int result = square(5);     // execution jumps into square( )
	cout << result << endl;
	return 0;
}
```

## Why Use Functions?
* **Reusability** - write logic once, call it many times.
* **Readability** - `calculateTax(income)` is clearer than 15 inline lines of math.
* **Maintainability** - fix a bug in one place instead of every copy-pasted instance.
* **Testability** - isolated functions are easier to test independently.

> [!IMPORTANT]
> Every meaningful, repeated, or logically distinct piece of behavior in a program should usually live inside its own function. This is the foundation of clean, modular C++ code.
