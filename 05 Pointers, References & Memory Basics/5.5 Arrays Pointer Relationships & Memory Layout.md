## Overview
This file ties together two interconnected conceptual topics: the deep relationship between arrays and pointers when dynamic allocation is involved, and how a running C++ program's memory is actually structured and segmented by the operating system.

---

## Part 1: Arrays & Pointer Relationships (Dynamic Context)
The array-pointer relationship covered in Section 4 was in the context of **stack-allocated** arrays. Dynamic memory extends this - you can now create arrays whose size is unknown at compiler time, manage them entirely through pointers, and pass them across function boundaries with full control.

### Dynamically Allocated Arrays Revisited

```cpp
int n = 5;
int* arr = new int[n];      // heap array - pointer and array are the same thing here

// Array indexing and pointer arithmetic are interchangeable
arr[0] = 85;
*(arr + 1) = 92;

for (int i = 0; i < n; i++) {
	cout << arr[i] << " ";   // identical to *(arr + i)
}

delete[] arr;
arr = nullptr;
```

> [!NOTE]
> For a dynamically allocated array, `arr` is simply a pointer to the first element - there is no hidden array object. This is why you must track the size yourself and must use `delete[]` to free it. The pointer and the array **are** the same thing.

### Passing Dynamic Arrays to Functions

```cpp
void fillArray(int* arr, int size, int value) {
	for (int i = 0; i < size; i++) {
		arr[i] = value;
	}
}

void printArray(const int* arr, int size) {
	for (int i = 0; i < size; i++) {
		cout << arr[i] << " ";
	}
	cout << endl;
}

int main() {
	int n = 5;
	int* data = new int[n];
	
	fillArray(data, n, 42);     // passes pointer, function fills it
	printArray(data, n);        // Ouput: 42 42 42 42 42
	
	delete[] data;
	return 0;
}
```

### Pointer to Pointer - Dynamic 2D Arrays
Creating a true dynamic 2D array (rows and columns both determined at runtime) requires a **pointer to a pointer**.

```cpp
int rows = 3, cols = 4;

// Allocate array of row pointers
int** matrix = new int*[rows];

// Each row pointer gets it's own array of columns
for (int i = 0; i < rows; i++) {
	matrix[i] = new int[cols];
}

// Use like a normal 2D array
matrix[1][2] = 99;
cout << matrix[1][2] << endl;     // 99

// Deallocation - must free each row before freeing the row pointer awway
for (int i = 0; i < rows; i++) {
	delete[] matrix[i];
}
delete[] matrix;
matrix = nullptr;
```

> [!WARNING]
> A dynamic 2D array (`int**`) is **not** stored contiguously like a stack 2D array. Each row is a separately allocated block that could be anywhere in memory. This means it loses the cache-locality benefit of stack arrays. For performance-critical 2D data, prefer a 1D array with manual index math (`arr[row * cols * cols + col]`) , or `std::vector<std::vector<int>`.

## Part 2: Memory Layout of a C++ Program
When your compiled C++ program runs, the operating system loads it into memory and divides that memory into distinct **segments**, each with a specific purpose.

```
High addresses
┌────────────────────────────┐
│ Stack                      │ ← grows downward
│ (local variables, frames)  │
├────────────────────────────┤
│                            │ 
│ (free space)               │
│                            │
├────────────────────────────┤
│ Heap                       │ ← grows upward
│ (dynamic allocations,      │
│ new / delete)              │
├────────────────────────────┤
│ BSS Segment                │
│ (uninitialized globals)    │
├────────────────────────────┤
│ Data Segment               │
│ (initialized globals       │
│ and static variables)      │
├────────────────────────────┤
│ Text Segment               │
│ (compiled machine code)    │
└────────────────────────────┘
Low addresses
```

### Text Segment (Code Segment)
Stores the compiled **machine code** of your program - the actual CPU instructions.
* Read-only - cannot be modified at runtime.
* Shared between processes running the same executable (OS optimization).

### Data Segment
Stores **global and static variables that are initialized** at the time of declaration.

```cpp
int globalCount = 10;         // lives in Data Segment
static in instanceCount = 0;  // lives in Data Segment
```

### BSS Segment
Store **global and static variables that are uninitialized** (or zero-initialized). The OS zero-fills this segment when the program loads.

```cpp
int globalTotal;        // lives in BSS - automatically zero
static int callCount;   // lives in BSS - automatically zero
```

### Heap
The region managed by `new` and `delete`. Grows **upward** (toward higher addresses) as you allocate, and shrinks as you free.
* Manual lifetime control.
* Large - limited only by system RAM.
* Fragmentation can occur if you allocate and free many different sizes.

### Stack
The region for **function call frames** - local variables, parameters, and return addresses. Grows **downward** (toward lower addresses) with each function call.
* Automatic lifetime - pushed on call, popped on return.
* Very fast allocation on deallocation (just moves the stack pointer).
* Small - typically 1-8 MB. Exceeding it causes a **stack overflow**.

```cpp
void functonA() {
	int localVar = 5;       // pushed onto the stack
	// when functionA returns, localVar is automatically destroyed
}
```

> [!TIP]
> Understanding that the **stack grows down** and the **heap grows up** explains several behaviors:
> * Why deeply nested recursion causes a stack overflow - each call adds a new frame eating into the limited stack.
> * Why local variables of a returned function become dangling - their stack frame is gone.
> * Why heap allocations persist past function scope - they're in a completely separate region.

| Variable type                    | Segment                      |
| -------------------------------- | ---------------------------- |
| Local variable inside a function | Stack                        |
| `new` - allocated memory         | Heap                         |
| Global variable (initialized)    | Data Segment                 |
| Global variable (uninitialized)  | BSS Segment                  |
| `static` local variable          | Data/BSS Segment (not stack) |
| String literals (`"hello"`)      | Text/Read-only Data Segment  |

```cpp
int globalInit = 5;       // Data Segment
int globalUninit;         // BSS Segment

int main() {
	int local = 10;            // Stack
	static in staticVar = 3;   // Data Segment (not stack - persists across calls)
	int* heap = new int(29);   // pointer on Stack, int on Heap
	
	delete heap;
	return 0;
}
```

> [!IMPORTANT]
> `static` local variables behave like globals in terms of memory location - they live in the Data or BSS segment and **persist for the program's entire lifetime** - but their scope is limited to the function they're declared in. They are initialized only once, the first time the function is called.
